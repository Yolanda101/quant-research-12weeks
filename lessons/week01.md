### 一行数据代表什么


研究面板的一行表示某只证券在一个观察时点的状态，主键为 observed_at 加 asset。先固定这个粒度，再连接财务和分类字段。日频价格不能直接连接多条公告记录，否则一行价格可能扩展成数行，样本权重也会随之改变。连接后需要复查主键唯一性、行数和证券覆盖率。


observed_at 记录被描述的时点，available_at 记录这条数据最早能进入研究系统的时点，可用时刻不得早于公开发布和实际接收时刻。它们分别保留。3 月 31 日的收盘数据可能在 15:00 之后才完整可用，不能把日期相同理解为同时可用。本周价格文件还单列 open_available_at 和 close_available_at，开盘价在 09:30 可用，收盘价及整行日线在 15:00 可用。财报还需 period_end 表示报告期，published_at 表示发布时刻。文本和分钟数据也沿用这套时间含义。



| 字段 | 含义和单位 | 检查要求 |
| --- | --- | --- |
| asset | 稳定证券代码 | 代码变更需有历史映射 |
| observed_at | 观察时点 | 保留时区 |
| available_at | 可用时点 | 记录来源和入库延迟 |
| raw_open、raw_close | 原始价格，元每股 | 不能以调整价格替代成交价 |
| volume | 成交数量，股 | 不能混用手、股或成交金额 |

| tradable | 该观察时点的交易状态 | 交易执行仍需核对实际成交时点 |



### 把面板写成矩阵


设同一时点有 n 只股票、p 个特征，X 的维度为 n 行 p 列。权重向量 w 有 n 个元素，w 乘 X 得到 p 个加权特征。矩阵本身不保存列单位，进入数组前要固定字段顺序，保存证券顺序，再检查权重顺序。仅检查维度还不够，顺序错位也会得到看似正常的数值。


手算三只股票的价格 100、80、50，成交量 1200、900、600，权重依次为 0.5、0.3、0.2。价格列加权为 84，成交量列加权为 990。两个结果单位不同，不能相加成为一个总分。把成交量从股换成手时，数值和字典单位要同时更新。后续模型的标准化参数还需要在训练期估计，本周先保留原始值和单位。


向量也用于记录每只股票的预期收益、持仓和缺失标记。缺失标记可以组成布尔向量，筛选时须同步作用于代码、特征和权重。删除一条缺失记录后，原权重之和可能不再为 1，不能沿用旧权重直接计算组合收益。每次筛选都保留删行原因，研究者才可以追踪样本为何变化。



### 代码核对


运行示例，先核对代码顺序和矩阵形状，再逐项核对加权结果。随后只交换证券顺序，观察同时调整权重前后结果是否一致。一个可复查的函数应明确接收哪些字段，输出哪些字段，并在进入矩阵计算前检查主键和排序。



### 代码示例

```python
import pandas as pd
import numpy as np

panel = pd.DataFrame({
    "asset": ["Q001", "Q002", "Q003"],
    "raw_close": [100.0, 80.0, 50.0],
    "volume": [1200, 900, 600],
})
field_units = {"raw_close": "元每股", "volume": "股", "market_cap": "元"}
x = panel[["raw_close", "volume"]].to_numpy()
w = np.array([0.5, 0.3, 0.2])
weighted = w @ x
print("资产:", panel["asset"].tolist())
print("特征矩阵:", list(x.shape))
print("单位:", field_units)
print("加权特征:", [round(float(v), 2) for v in weighted])
```

```text
特征矩阵: [3, 2]
单位: {'raw_close': '元每股', 'volume': '股', 'market_cap': '元'}
加权特征: [84.0, 990.0]
```

## 02　数据质量和历史股票池

保留退市证券，核对重复、缺失和异常，区分数据行数和独立信息。

### 本节要解决的问题


一张表有六行记录，能否全部进入研究？当前还在交易的股票，能否代表过去的投资范围？本节分别检查记录质量和证券资格。质量报告保留原始计数，历史股票池保留过去上市和退市的证券，最后再按明确规则生成可研究样本。

### 先查原因，再决定处理


手算六行小表：Q002 在同一日期出现两次，Q003 有一条价格缺失，Q001 有一条价格为负。重复主键的多余行数为 1，缺失价格数为 1，非正价格数为 1。缺失值不会自动计入非正值，因此两项要分别检查。报告还需写出检查分母，说明异常占全部原始记录还是占去重后的记录。


原始值保留在输入文件，清理结果另存。每次修改写明主键、问题、旧值、处理方式和理由。收盘价缺失可能来自停牌，也可能来自下载中断。停牌需要保留其交易状态；下载中断需要核对来源。把两类缺失都填成前一天价格，会混淆估值、交易资格和观测缺口。


成交量为零也需要结合交易状态解释。零成交量不能凭空变成可成交价格，成交量单位错误则可能造成数百倍的换手偏差。检查价格单位、成交量单位和市值单位后，再比较极端值。对异常值的阈值和处理方法，本周写入报告，后续只在训练范围内估计需要拟合的参数。



### 按历史状态重建股票池


本周用上市日期包含、退市日期不包含的区间约定。证券在 listed_at 当天进入记录范围，在 delisted_at 当天退出。该字段表示课程数据的资格边界，不能直接推断真实市场的最后成交日。本题假设这些状态事件在生效前已公开。真实研究需要另查上市、退市、停牌和交易限制的历史记录，并保存事件可用时点。


2021 年 3 月 31 日，Q001、Q002、Q003 已上市，Q004 尚未上市，因此历史股票池有三只。到 2023 年底，Q001 和 Q004 已退出，只剩 Q002、Q003。将这个当前名单回填到 2021 年，会遗漏 Q001。遗漏的证券恰好在后续退出，样本选择已经使用了研究时点以后才知道的信息。


上市资格只是第一层筛选。当日能否下单，还要检查停牌、价格限制、订单方向和资金。后续若设置上市满若干观察日的要求，应按各日已有历史计算，保留生效日期。行业分类和指数成员也需要历史版本，不能把今天的分类全部回填到过去。



### 行数不等于独立信息量


假设两天中，股票甲的收益为 1%、负 1%，股票乙为 2%、负 2%。它们各自均值为零。按样本公式除以 2 减 1，甲的方差为 0.0002，乙的方差为 0.0008，协方差为 0.0004。协方差矩阵的对角线放方差，非对角线放共同变化。


两只股票等权组合的每日收益为 1.5%、负 1.5%，样本方差为 0.00045，也等于 w 转置乘协方差矩阵再乘 w。两只股票在这里同向变化，增加股票数没有提供同样数量的独立冲击。六万条面板记录可能集中在二十个日期，日期内有共同市场冲击，相邻日期也可能相关。


这个小例子只用于核对公式。正式估计需要更多日期，并说明样本方差的估计对象。后续计算标准误和验证结果时要保留日期结构，不能把每行当成独立抽样。本周质量报告同时记录行数、证券数、观察日数和每日覆盖率，避免只用总行数描述数据规模。



### 代码核对


示例先重建历史股票池，再输出原始质量计数。质量小表是独立故障样本，不能作为主研究面板历史可用性的证据。将日期改到 Q004 上市之后，检查成员变化。随后把缺失值改为零，观察缺失计数和非正计数如何变化，并写明这种替换为何改变了问题含义。



### 代码示例

```python
import pandas as pd

assets = pd.DataFrame([
    ["Q001", "2015-01-05", "2022-06-30"],
    ["Q002", "2014-01-06", None],
    ["Q003", "2019-07-01", None],
    ["Q004", "2021-04-15", "2023-09-29"],
], columns=["asset", "listed_at", "delisted_at"])
for column in ["listed_at", "delisted_at"]:
    assets[column] = pd.to_datetime(assets[column])
def pool_at(date):
    date = pd.Timestamp(date)
    active = (assets["listed_at"] <= date) & (
        assets["delisted_at"].isna() | (date < assets["delisted_at"])
    )
    return assets.loc[active, "asset"].sort_values().tolist()
historical_pool = pool_at("2021-03-31")
current_pool = pool_at("2023-12-31")
lost_assets = sorted(set(historical_pool) - set(current_pool))
print("历史股票池:", historical_pool)
print("当前股票池:", current_pool)
print("直接回填会遗漏:", lost_assets)

quality = pd.DataFrame([
    ["2021-03-31", "Q001", 99.0],
    ["2021-03-31", "Q002", 70.0],
    ["2021-03-31", "Q002", 70.0],
    ["2021-03-31", "Q003", None],
    ["2021-04-01", "Q001", -1.0],
    ["2021-04-01", "Q003", 50.0],
], columns=["observed_at", "asset", "raw_close"])
print("质量计数:", {
    "rows": len(quality),
    "duplicate_keys": int(quality.duplicated(["observed_at", "asset"]).sum()),
    "missing_close": int(quality["raw_close"].isna().sum()),
    "nonpositive_close": int((quality["raw_close"] <= 0).sum()),
})
```

## 03　信息可用时间和财报修订

按信号时点筛选当时可见的报告，保留发布、入库和修订记录。

### 本节要解决的问题


Q001 的 2020 年年报账面权益最初记录为 120，之后修订为 135，单位均为百万元。研究 2021 年 3 月 31 日 15:00 的信号，应使用哪一个数？答案取决于可用时刻。报告期、发布日期和数据库当前显示的最新版本，都不能单独决定历史信号能看到什么。


period_end 表示财务数据覆盖的期间终点。published_at 表示资料公开发布的时刻。available_at 表示本研究流程最早能够读取该版本的时刻，它还可能包含供应商处理和入库延迟，取公开、实际接收和必要处理完成之后的最早可用时刻。version 标记同一份资料的版本。四项分别保存，才能解释同一报告期为什么在不同研究时点出现不同数值。输入检查应验证 available_at 不早于 published_at，并记录实际接收依据。



### 手画一条信息时间线


Q001 初版在 3 月 30 日 18:00 发布，3 月 31 日 08:30 可用，值为 120。信号在 3 月 31 日 15:00 形成，所以初版可以进入特征。修订版在 4 月 1 日 18:00 发布，4 月 2 日 08:30 可用，值为 135。该修订晚于信号，应保留在版本表中，不能覆盖历史特征。


Q002 的 2020 年年报在 3 月 31 日 16:30 才可用，因此同日 15:00 的信号仍需读取早已可见的 2019 年数据 70。新一期数值 80 只在其可用时刻以后进入研究。看到日期同为 3 月 31 日就进行连接，会把当日盘后信息放进盘前或收盘信号。


现在手算信号时点的两条输出：Q001 为 2020 年期末、版本 1、数值 120；Q002 为 2019 年期末、版本 1、数值 70。再将截止时刻推到 4 月 2 日 09:00，Q001 才可以读取修订值 135。将截止时刻改变以后重新连接，能够检查版本规则是否真正作用于每次研究。



### 先过滤可见版本，再选择记录


第一步按 available_at 小于等于 signal_at 筛选。第二步在可见记录中确定最新报告期。第三步在同一报告期内选择最近可用版本。示例按证券、报告期、可用时刻和版本号排序，保留每只证券最后一条。输入若存在相同排序键的冲突值，应先报告冲突，避免让输入文件的偶然顺序决定结果。


按时间连接工具可以提高效率，但工具不会替你定义报告期和修订含义。研究者需要明确允许多旧的财报、如何处理缺失、是否需要等待入库，以及多个报表字段是否共享同一发布时间。连接完成后，保存所选记录的原始键和可用时间，特征表才可以追回来源。


如果只有报告日期，没有日内时刻，就不能自行假定开盘前已经可用。可以依据数据说明设定一个明确的保守可用时刻，并将其记入配置；另做时间延迟敏感性检查。这里的处理条件必须写进报告，不能悄悄将所有公告都移到最有利的位置。



### 条件期望里的信息范围


将截至时点 t 已可见的信息记为 F_t，预测目标可写成 E[y | F_t]。这个符号要求预测只依赖当时信息，并不保证预测准确。原始行情、已发布财报、当时行业分类都可能属于 F_t，后续修订和未来收益不属于这个集合。每个特征都应能回答自己属于哪个时点的信息集合。


例如训练期中，某个预先定义的信号组有两期收益 4% 和负 2%，组内样本均值为 1%。它可以作为该组条件均值的简单估计。若先查看未来收益，再把赚钱样本放进一组，组别本身已依赖目标，得到的均值不能代表可执行预测。条件划分必须由预测时点可见的字段决定。


本周不估计复杂预测模型。先检查条件变量的来源、时间和版本。把 Q001 修订值当成初版，会改变条件信息；只按当前数据库提取历史值，也可能产生同样问题。保存初版和修订记录，才能在第三周的未来数据扰动实验中核对历史特征是否被后来的数据改变。

### 代码示例


## 04　成交价格和收益标签

分开核对成交价格、现金分红和调整价格，明确每个标签的起止时间。

### 本节要解决的问题


Q001 以每股 100 元入场，之后以 101 元退出，持有期获得每股 2 元现金分红。原始价格涨幅为 1%，持有期总收益为 3%。本节把这笔交易拆成价格、现金和时间记录，建立后续因子评价使用的收益标签。


统一时间线为 3 月 31 日 15:00 形成信号，4 月 1 日 09:30 入场，5 月 3 日 09:30 退出。它们是合成日历中的教学观察日。信号可以使用什么数据，按 available_at 判断；订单能否成交，按实际下单和成交条件判断；标签何时完整可知，按退出和相关现金信息判断。三个问题分别记录，避免只用一个日期字段承担全部含义。



### 先核对一笔现金账


手算买入 10 股需要 1000 元，退出卖出得到 1010 元，现金分红为 20 元，期末资产为 1030 元。暂不计税费、再投资和融资，总收益为 1030 除以 1000 再减 1，得到 0.03。每股公式为 exit_price 加 cash_dividend，再除以 entry_price，最后减 1。


现金分红只计入符合持有资格的分配。数据表需保存除权时点 ex_at、支付时点 paid_at 和每股现金。若退出时尚未支付，需要明确应收股息如何估值、何时进入可用现金。本周样例的分红在持有期间完成支付，因此直接进入期末资产。税费和交易成本另加字段，不隐藏在价格里。


公司拆分、合并和配股还可能改变持股数量。遇到这类事件，应同时核对数量、现金和价格，不能沿用固定股数的简化公式。退市、停牌和无法成交也需要单独处理，记录实际退出规则、残余持仓或现金回收。缺失退出价格不能直接填成零收益，后续日期的价格也不能无条件代替约定成交价。



### 调整价格的用途


原始价格用于成交和资金核算。调整价格按公司行动规则形成连续序列，可以辅助比较收益。本周只提供原始成交价格和分红，不人为构造调整端点或通用复权乘数。若另有经过核实的含分红总回报序列，可以用它交叉核对收益；其指数点位不能替代实际卖出价。


不同来源的调整方法可能包含不同分红处理和基准日期。若先用包含分红的调整价格计算收益，再增加现金分红，会重复计入。数据字典需要写明调整方法、基准和版本，抽样核对原始价加现金的结果。历史特征若使用调整序列，还需检查后续公司行动是否改变过去输入值。


价格文件的 open_available_at 和 close_available_at 分别说明开盘价和收盘价何时可读，整行日线的 available_at 不能提前开放收盘字段。交易状态也要沿时间保存。信号日可以下单并不代表次日一定成交。次日停牌时按预设规则记录未成交或延期，并把真实成交时点带入标签。决定是否成交时只能读取订单执行当时已经知道的状态；不能事后挑选更好的退出日期，再把收益当作原规则结果。



### 对数收益和复利


简单收益记为 r，资产增长倍数为 1 加 r。对数收益为 log1p(r)，本例约为 0.029559。用 expm1 将它还原为 0.03。连续区间的简单收益需要先转换成增长倍数再连乘，对数收益则按时间相加。所有价格和增长倍数必须满足对应计算的定义范围。


手算先涨 10% 再跌 10%，本金 100 变成 110，再变成 99，累计收益为负 1%。简单收益相加得到零，不能表示这段持有期的结果。两个对数收益相加等于 99 除以 100 的对数。时间相加的性质适用于同一资产的连续区间，不能直接把不同股票的对数收益按权重平均作为精确组合对数收益。


组合的简单收益在同一持有区间、期初权重已知、现金流口径一致时，可以按期初权重加权。中途调仓、分红支付和再投资会改变资金路径，需要更细的现金账户。后续组合实验使用逐期持仓和现金账，本周先把一笔交易的每个金额复算清楚。



### 代码核对


运行示例，核对原始价收益、含分红收益和期末资产。将分红改成零，再把退出价改为 98，检查输出是否符合手算。保留完整计算精度，只在显示阶段使用 round。



### 代码示例

```python
from math import log1p, expm1

signal_at = "2021-03-31T15:00:00+08:00"
entry_at = "2021-04-01T09:30:00+08:00"
exit_at = "2021-05-03T09:30:00+08:00"
entry_price = 100.0
exit_price = 101.0
cash_dividend = 2.0
quantity = 10
raw_price_return = exit_price / entry_price - 1
total_return = (exit_price + cash_dividend) / entry_price - 1
log_return = log1p(total_return)
ending_value = quantity * (exit_price + cash_dividend)
print("信号、入场、退出:", [signal_at, entry_at, exit_at])
print("原始价格收益:", round(raw_price_return, 6))
print("含分红收益:", round(total_return, 6))
print("对数收益:", round(log_return, 6))
print("对数还原:", round(expm1(log_return), 6))
print("10 股期末资产:", round(ending_value, 2))
```

## 05　时间划分和跨界标签

按日期保留开发范围，检查标签结束时间，登记封存测试边界。

### 本节要解决的问题


一条样本的信号在 2021 年形成，收益到 2022 年 2 月才结束。若模型在 2022 年 1 月 1 日拟合，该样本能否训练？仅按信号年份切分还不够。标签在拟合时没有结束，结果尚不可知，必须从当次拟合样本中排除或按预先声明的延迟规则处理。


本课程开发范围为 2016 至 2023 年。初始研究范围为 2016 至 2021 年，2022 至 2023 年用于开发期滚动评价。最终测试范围为 2024 至 2025 年，本周只登记边界和执行条件，不读取该区间的价格、标签或评价统计。测试边界不能根据结果好坏移动。



### 为样本保留区间


每条样本至少保存 signal_at、entry_at、exit_at 和 label_available_at。signal_at 决定特征可见范围，entry_at 和 exit_at 描述实际持有区间，label_available_at 决定训练时能否使用完整目标。标签还依赖晚到的公司行动资料时，可用时间可能晚于退出时点，不能将两者自动设成相同。


手画四条样本。A 在 2021 年 10 月形成信号，12 月 1 日标签可用；B 在 11 月形成，12 月标签可用；C 在 12 月 31 日形成，2022 年 2 月才可用；D 在 2022 年 1 月形成，3 月可用。首次拟合时点为 2022 年 1 月 1 日。A、B 可以训练，C 跨过边界，D 属于后续开发期评价样本。


这次示例用严格早于 fit_at 的条件选择训练标签。若研究流程允许在某个同刻更新，需要写出先接收资料、再拟合、后下单的顺序，并处理数据延迟。给边界加减一天不能替代时刻定义，尤其在日内数据和公告数据中，同日事件的先后会直接改变可见范围。



### 按日期整组推进


横截面预测以日期为组。同一日期的不同股票要进入同一个验证折，避免把当天共同市场信息同时放入训练和评价。一个开发期滚动流程可以先用截至 2021 年底已经可知的样本拟合，再评价 2022 年上半年的信号，之后向前推进。每个折都记录拟合时刻、训练信号范围、训练标签截止和评价信号范围。


在下一个折开始时，较早的评价结果若已完整可知，可以按预先安排加入训练。2022 至 2023 年仍属于开发数据，因此基于这些结果作出的选择需要写入试验台账。若要评价一次完整选参过程，后续采用内层选择参数、外层记录样本外表现的结构，本周先建立可以支持这些切分的时间字段。


缺失值处理、标准化、特征筛选和模型拟合都读取训练范围。全样本均值虽然看起来只是一个预处理数字，也包含后续数据的分布信息。第一个折结束后重新估计参数时，保存这次拟合范围和结果，不能用最终训练参数反过来覆盖早期预测。



### 重叠标签带来的依赖


若每个观察日都生成未来二十日收益，相邻两条标签会共享大量持有日。同一个市场冲击会多次出现在标签中，记录数增加不等于独立信息等比例增加。评价时应保存日期结构，后续用区块重采样等方法研究不确定性。


两个半开区间 [a,b) 和 [c,d) 相交的条件是 a 小于 d，且 c 小于 b。画出两个持有区间，可以检查训练标签是否跨入需要隔离的评价范围。本周先标出跨界样本；第六周再根据具体验证结构实施 purging 和 embargo，分别记录剔除原因和剩余训练范围。


相邻标签重叠通常导致样本依赖。训练时使用未来才可知的标签还会造成时间泄漏。这两项需要分别检查，因为即使全部训练标签已在拟合前结束，评价标签之间仍可能重叠。报告先说明预测对象和时间范围，再选择合适的误差估计方法。



### 代码核对


示例只筛选首次拟合可用样本并登记封存边界，尚未训练模型。将 C 的标签可用时刻改到边界之前，再核对其归属。随后添加一个同日期的第二只股票，确认它跟随同一个日期分组，不被随机分到另一折。



### 代码示例

```python
import pandas as pd

labels = pd.DataFrame([
    ["A", "2021-10-29T15:00:00+08:00", "2021-12-01T09:30:00+08:00"],
    ["B", "2021-11-30T15:00:00+08:00", "2021-12-30T09:30:00+08:00"],
    ["C", "2021-12-31T15:00:00+08:00", "2022-02-01T09:30:00+08:00"],
    ["D", "2022-01-31T15:00:00+08:00", "2022-03-01T09:30:00+08:00"],
], columns=["sample", "signal_at", "label_available_at"])
for column in ["signal_at", "label_available_at"]:
    labels[column] = pd.to_datetime(labels[column], utc=True)
fit_at = pd.Timestamp("2022-01-01T00:00:00+08:00")
validation_end = pd.Timestamp("2024-01-01T00:00:00+08:00")
earlier_signal = labels["signal_at"] < fit_at
fit_samples = labels.loc[earlier_signal & (labels["label_available_at"] < fit_at), "sample"].tolist()
crossing_samples = labels.loc[earlier_signal & (labels["label_available_at"] >= fit_at), "sample"].tolist()
validation_samples = labels.loc[(labels["signal_at"] >= fit_at) & (labels["signal_at"] < validation_end), "sample"].tolist()
sealed_range = ["2024-01-01", "2025-12-31"]
print("可用于首次拟合:", fit_samples)
print("跨界标签:", crossing_samples)
print("开发期评价样本:", validation_samples)
print("封存范围:", sealed_range)
```

## 06　文本、分钟数据和研究数据包

追踪文本、编码器、分钟线的可用版本，组装能逐条复查的数据包。

### 本节要解决的问题


未来课程会加入公告文本、预训练编码器和分钟执行实验。本周先确认这些资料在历史时点是否存在，并建立文件清单。一个可以复查的数据包，需要解释每个文件的内容、版本、时间和生成过程，也需要让抽查者追回具体输入行。



### 文本保留内容版本


每份文本保存 document_id、asset、published_at、available_at、version 和正文。文本发布日期可能早于实际入库时刻，网页也可能在发布后修改。若只保存当前页面内容，研究者无法确认历史信号读到的是初版还是后来改写的版本。原文保存后计算内容哈希，修改正文会得到不同指纹。哈希只能核对本次保存的内容，历史可用性还需要来源记录和时点依据。


本例 D001 在 3 月 31 日 08:45 已可用，D002 在 16:45 才可用，所以 15:00 信号只能使用 D001。手算这个筛选结果，再把 D001 追加一个盘后版本，检查历史文本是否仍保留初版。重复公告、转载和跨站复制需要有识别规则，避免同一条信息多次进入特征。


文本特征还包含拟合步骤。后续使用 TF-IDF 时，词表、词频权重和其他变换只在当前训练范围内估计。先在全部文本上建词表，再切分年份，会把后续语料的词汇和分布带入早期流程。本周在清单中登记这些变换的拟合范围，暂不挑选最能提高收益的分词和清理规则。



### 编码器也有可用时点


冻结编码器参数，只能保证本次训练时不再更新它。历史评价还要记录编码器名称、版本、训练语料截止、发布时间和文件哈希。训练材料包含未来公告，或模型在信号形成以后才发布，都需要按历史使用条件审查。训练截止说明不完整的版本，先标为待核实。


本例 lexicon-2020 的训练截止和发布时间都在 2021 年信号之前，可以进入当前对照；future-encoder-2022 的训练截止为 2022 年底，2023 年 1 月才发布，不能用于这条 2021 年信号的历史可执行评价。后续若以今天可用资料做另一个研究任务，应另立评价条件，避免两种信息范围混写在同一结果表中。



### 分钟线结束以后才完整


一根分钟线同时保存 bar_start、bar_end 和 available_at。09:30 至 09:31 的分钟线在 09:31:00 可用，09:31:10 发单时可以读取。下一根线到 09:32 才结束，09:32:00 才可用，不能提前使用其中的价格或成交量。用分钟起始时间作为标签时，更需要核对实际覆盖区间。


手算 09:31:10 的可见列表，只有结束于 09:31 的分钟线。第十周分拆订单时，子单量可以参考此前可见的历史成交量曲线。当日未来成交量只在发生之后可见，当日完整 VWAP 是事后成交基准，不能在早盘决定子单量时提前读取。


分钟样本还需要记录价格单位、成交量单位、空分钟、停牌和跨日处理。秒级时间戳并不自动保证数据准确，供应商聚合延迟和修订仍可能改变 available_at。清单中说明时间来自交易所事件、数据商记录还是本地接收，后续执行实验才能检查假设是否成立。

### 代码核对


示例分别筛选文本、编码器和分钟线。三个截止时刻对应不同任务：文本和编码器用于信号，分钟线用于后续订单。运行后修改订单时刻，观察分钟线何时进入可见列表，确认没有把信号时刻机械地用于全部环节。



### 代码示例

```python
import pandas as pd

signal_at = pd.Timestamp("2021-03-31T15:00:00+08:00")
documents = pd.DataFrame([
    ["D001", "2021-03-31T08:45:00+08:00"],
    ["D002", "2021-03-31T16:45:00+08:00"],
], columns=["document_id", "available_at"])
documents["available_at"] = pd.to_datetime(documents["available_at"], utc=True)
visible_documents = documents.loc[documents["available_at"] <= signal_at, "document_id"].tolist()
encoders = pd.DataFrame([
    ["lexicon-2020", "2020-12-31T00:00:00+08:00", "2021-01-15T09:00:00+08:00"],
    ["future-encoder-2022", "2022-12-31T00:00:00+08:00", "2023-01-15T09:00:00+08:00"],
    ["undocumented-encoder", None, "2021-01-20T09:00:00+08:00"],
], columns=["encoder", "training_cutoff", "released_at"])
for column in ["training_cutoff", "released_at"]:
    encoders[column] = pd.to_datetime(encoders[column], utc=True)
eligible = (encoders["training_cutoff"] <= signal_at) & (encoders["released_at"] <= signal_at)
eligible_encoders = encoders.loc[eligible, "encoder"].tolist()
bars = pd.DataFrame([
    ["2021-04-01T09:31:00+08:00", "2021-04-01T09:31:00+08:00"],
    ["2021-04-01T09:32:00+08:00", "2021-04-01T09:32:00+08:00"],
], columns=["bar_end", "available_at"])
bars["available_at"] = pd.to_datetime(bars["available_at"], utc=True)
order_at = pd.Timestamp("2021-04-01T09:31:10+08:00")
visible_bars = bars.loc[bars["available_at"] <= order_at, "bar_end"].tolist()
print("可见文本:", visible_documents)
print("可用编码器:", eligible_encoders)
print("下单前可见分钟线:", visible_bars)
```
